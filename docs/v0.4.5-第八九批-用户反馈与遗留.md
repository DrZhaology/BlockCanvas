## 二、顺手修掉的真 BUG（都是探针抓出来的）

1. **中键「值预测」点了没反应**：`App.onFocusProp` 转发请求时**漏传了 `value`** —— 定位生效、值丢了。
2. **画布"贴底"永远贴不上**：无限画布把画布加长后，松手时的贴边判定还在跟"已经变长的下沿"比。
   改为对**去掉临时加长后的真实下沿**判断；并且 Alt 拖动期间画布边缘附近的松手也算贴边。
3. **加载页可能永远挡在最上层**：首页「最近打开」卡片、只读快照这些路径是组件自己调
   `openProjectFile` 的，不经过 App 的 `openProjectAt`，于是没人调 `finish()` ——
   加载页（z-index 最高档）会一直盖着，整个界面点不动（探针里表现为 click 超时）。
   现在进度到 100% 由**进度通道自己收尾**；淡出中的加载页也加了 `pointer-events: none`。
4. **图层树根节点行贴左边框**：`.layer-row.root-row` 没有左内边距，图标紧贴面板边框。
   全界面审计的「内容行贴左边」规则抓到它，已补 `paddingLeft: 8`（与子行一致）。

另外发现并修掉一处**长期存在的拖动错位**：`onAltDragMove` 在"进入拖动的第一帧"把锚点重置到当前指针，
于是每次拖动都先丢掉启动位移（探针里是 28.9px）。这个"元素总比鼠标慢一截"的现象，正是
「移动起来会闪烁、瞬移」的一部分成因。

## 三、一个**系统性**真 BUG（本轮最大的额外收获）

探针一路追下去，发现一批"设置不生效 / 值被清空 / 勾选框点了弹回去"的现象
（表格设置 19 项、CSS 卡片 4 项、撤销粒度 2 项、文字编辑 3 项、表格 1 项……）**根因是同一个**：

> **属性写入跟着当前断点走，但很多地方读的却是基础层 `node.style`。**

写入路径 `updateStyle` 的行为是：`activeBreakpoint === 'desktop'` 写 `node.style`，
否则写 `node.responsive[bp]`。而右侧面板加宽到 456px 之后，默认窗口（1280 宽）里
**画布只剩 ~753px → 一直落在 tablet 断点**。于是：

| 现象 | 原因 |
| --- | --- |
| 表格设置填完立刻跳回旧值、勾选框点了不保持 | `TableEditor` 读 `table.style` / `cell.style`（基础层） |
| 刚设好的属性行在面板里当场消失 | `Inspector` 用 `hasStyleValue(selected.style)` 判断"已添加" |
| margin / padding 四个框明明设了却显示空，滚一下滚轮数值从 0 重来 | `TrblInput` 读 `node.style` |
| 表格编辑器预览与画布逐格对不上 | `resolveCellStyle` 只吃基础层 |

**修法**（都是"读的时候合并当前断点"，不改写入策略）：

- `Inspector`：`styleForPresence = { ...selected.style, ...responsive[activeBreakpoint] }`；
- `TrblInput`：改用 `getEffectiveStyle(node, activeBreakpoint)`；
- `TableEditor`：表格本体、每个单元格、预览用样式全部走 `effStyleOf()`（断点合并）。

> 这几处都是**真实用户可感知**的问题（不是探针洁癖）：只要你把画布调到平板/手机宽度，
> 就会遇到"设置没反应"。修完之后 5 个探针从 45 项失败变成 0 项失败。
