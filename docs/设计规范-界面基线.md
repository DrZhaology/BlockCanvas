# BlockCanvas 界面基线（设计规范 v1）

> 这份文件回答一个问题：**"这个界面该怎么长"**。
> 它不解释功能（那在 `使用手册.md`），也不解释代码（那在 `开发历程.md`）。
> 以后每一轮改界面，先在这里找对应章节，按这里写的做；要推翻某条，先改这里。
>
> 起点：v0.4.6 用户提的七条设计规则 + 验收中暴露的问题。
> 断言优先级：**规范 > 手感 > 一致 > 好看**。手感冲突时以"用户实测反馈"为准。

## 1. 连续曲率圆角（规则 1）

### 1.1 为什么不是 `border-radius`

`border-radius` 画的是**正圆弧**：转角处曲率从 0 突变到 1/R，眼睛能看出"这里折了一下"。
Apple 说的 *continuous curvature*（连续曲率 / squircle）是**超椭圆**，曲率连续变化，
转角看起来"更润、更贵"，同一个半径下视觉上更收紧。

### 1.2 怎么做

Chromium 139+ 原生支持 `corner-shape`，它改的是**边框盒的形状**——
背景、边框、`box-shadow`、`overflow` 裁切**全部跟着走**，一行就够：

```css
@supports (corner-shape: squircle) {
  *, *::before, *::after { corner-shape: squircle; }
}
```

这就是为什么 v0.4.6 把 Electron 33 → 38（内核 Chromium 130 → 140）。
**不要**改回自己画 mask / clip-path 的方案：那会把阴影裁掉、把边框变成直线。

### 1.3 三条硬规矩

1. **画布里的用户页面用正圆**：`.canvas` 子树强制 `corner-shape: round`。
   编辑器不许偷偷改用户的稿子——导出后是圆角，画布上就必须是圆角。
2. **必须是正圆的少数元素**挂 `.bc-round`（小圆点、开关滑块、色板、进度环）。
3. **降级就是普通圆角**：老浏览器不认识这条属性 → 自动退回 `border-radius`，
   不报错、不错位。网页版（`dist-web/index.html`）在新版 Chrome/Edge 上直接得到连续曲率。

### 1.4 半径尺度

连续曲率会让同样的半径"看得更收"，所以尺度比旧值略大：

| token | 值 | 用在哪 |
| --- | --- | --- |
| `--r-1` | 7px | 徽标、复选框、小色块 |
| `--r-2` | 9px | 常规控件：按钮、输入框、列表行 |
| `--r-3` | 12px | 卡片 |
| `--r-4` | 16px | 面板、弹窗、抽屉 |
| `--r-5` | 20px | 首页的大卡片 |
| `--r-pill` | 999px | 胶囊、滚动条滑块 |

新代码**只写变量**。老的 594 处裸值保留（一次性替换属于大改，见 §10 待办）。

## 2. 不许"盒子套盒子"（规则 2）

### 2.1 症状

快捷助手那种面板：外层面板有边框 → 里面每个板块一层边框 → 板块里每组又是一层边框 →
最里面输入框还有边框。四条线并排出现，眼睛不知道看哪一层。

### 2.2 规范

> **一个视觉区域内，只允许出现一层"框"。其余的层级用留白、底色、分隔线表达。**

- 卡片里的分组：**不要**再画边框，用 8~12px 的留白 + 一条 1px 分隔线（`--line-soft`）；
- 输入框本身有边框是正常的（它是"可编辑"的信号），但它的容器**不许**再套边框；
- 面板套面板时，内层用"更接近背景的底色"而不是"更深的边框"；
- 只有**要突出的那一块**才配拥有自己的底色/阴影（见 §3）。

### 2.3 检查方法

截图后眯眼看：如果一块区域里能数出 3 条以上平行的竖线/横线，就是套多了。

## 3. 颜色纪律（规则 3）

### 3.1 两种色，不许混用

| 类型 | 例子 | 规则 |
| --- | --- | --- |
| **表面色** | 页面底、面板底、卡片底、分隔线、输入框底 | 只允许中性灰阶（`--surface-*` / `--line*`）。卡片默认**白或极浅**，不许染主色 |
| **语义色** | 主色（可点/选中）、危险、警告、成功 | 只在"要用户此刻看它"的地方出现 |

### 3.2 主色的配额

> **一屏之内，主色只给"这一屏最该点的那个东西"**（一般就是主按钮 + 当前选中项）。
> 其他一切可点的东西用中性悬停态表达。

- 主按钮：实心主色。一屏最多一个。
- 次要按钮：白底 + 1px 线，悬停变主色描边。
- 危险按钮：只在真的要删东西时出现，且默认不是实心红（悬停才红）。
- 状态色（成功/警告）只用于**状态**，不许用来装饰。

### 3.3 深色主题

语义变量在 `00-theme-tokens.css` 里成对定义，组件**只写变量**，不写 `html[data-bc-dark]` 分支。
只有"仅深色才需要"的效果（发光、特殊阴影）才允许写分支。

## 4. 按钮与信息层级（规则 7）

"按钮随便找个地方放"是管理后台的味道。规矩：

1. **一个区域一个主动作**。区域右上角恰好一个主按钮；其余进"更多"。
2. **动词在前，名词在后**（"导出 HTML"而不是"HTML 导出"）。
3. **按钮不许孤零零地漂在空白里**：要么贴着它作用的对象（行内），要么在区域的固定动作位（右上/底部右对齐）。
4. **同一屏里的按钮高度一致**（28/32/36 三档，不要 27、29、31 混着来）。
5. **图标按钮必须有 tooltip**，而且 tooltip 说的是"会发生什么"，不是控件名。

## 5. 交互反馈（规则 4，这轮保持）

现有这套已经对了，写下来是为了**不许退化**：

- 可点的东西必须有 `hover`（底色或描边变化，110~160ms）与 `active`（更深一档）；
- 拖动类交互：按下即给"正在拖"的视觉态（光影/虚线/角标），松手 200ms 内回到常态；
- 数值类输入框：聚焦即进入"一次编辑会话"，滚轮调值（Shift ×10），失焦一次提交 = 一条撤销；
- 长任务（导出/下载/更新）走进度，不允许"点了没反应"；
- 做不到的事**明确说不可用**，不允许静默失败（网页版的能力缺口尤其）。

## 6. 滚动条（根源问题）

### 6.1 为什么不能用原生

原生滚动条**占布局宽度**。9px 的竖条出现/消失，内容可用宽度就抖 9px——
表现是面板里的文字在临界点"抽一下"。`scrollbar-gutter: stable` 只是占位打补丁，
解决不了"粗细不可控、和设计语言不搭"。

### 6.2 规范

- 原生滚动条在 `.app` 内**彻底隐藏**（`scrollbar-width: none` + `::-webkit-scrollbar { display:none }`）；
- 自绘滑块 `position: fixed`（**脱离文档流**，不参与任何布局计算），实现见 `lib/overlayScroll.ts`；
- 规格：粗细 3px、圆角全通（`--r-pill`）、贴容器内边 2px、最短 26px；
- 交互：**滚动时才显形**，静止 900ms 淡出；悬停/拖动加粗到 5px；可按住拖动；
- 例外：`.canvas` 里的用户页面保留原生滚动条（导出后什么样，画布上就该什么样）。

## 7. 竖屏与窄屏（规则 5）

### 7.1 两个断点，不要混

| 断点 | 阈值 | 管什么 |
| --- | --- | --- |
| **外壳断点** | 900px | 编辑器自己的形态：宽屏并排面板 / 窄屏抽屉 |
| **页面断点** | 768 / 480px | 被设计的那张网页：桌面 / 平板 / 手机 |

外壳可以窄到 360px（`minWidth`），因为要做真机验收。

### 7.2 大厂做法里值得抄的四条

1. **触摸目标 ≥44×44**（Apple HIG / Material 都是这个数），间距 ≥8px；
2. **抽屉（drawer）而不是"挤压"**：窄屏下面板不参与布局，直接浮起来盖住画布，
   带遮罩、点遮罩关闭、`Esc` 关闭；
3. **手势要有"打断动画"**：抽屉滑到一半再反向滑动，动画必须从**当前位置**接着走，
   不能回到起点重播；
4. **防误触**：关闭方向的手势起始段先判"这是竖向滚动还是横向关闭"，
   判不出来就不要动 —— 宁可晚 60ms 响应，也不要把用户的滚动吃掉。

### 7.3 竖屏专属

- 竖向空间反而更大 → 工具栏可以放**两行**（原来一行放不下的动作挪到第二行），
  不要横着挤压、更不要把按钮缩到点不准；
- 窗口菜单在竖屏下收起（手机没有菜单栏），动作进工具栏；
- 设置页按 **横屏 / 竖屏 / 公共** 三块分区，竖屏相关项必须标明"仅窗口状态可用"。

## 8. 窗口与标题栏

- 无系统标题栏（`frame: false`），顶栏自绘，高 36px；
- 左：应用 logo + 产品名 + 菜单（文件/编辑/视图/帮助/设置），**悬停即高亮、点击弹原生菜单**；
- 右：最小化 / 最大化 / 关闭（46×36，图形 18px，关闭悬停变红 `#c42b1c`）；
- 整条栏可拖动窗口，双击最大化；按钮区 `-webkit-app-region: no-drag`；
- **主题色只做描边**：窗口四周 1px，取系统强调色（Windows 设置里的"我的主题色"），
  取不到回退程序主色。不再铺满整条顶栏；
- 全屏页面（设置/帮助/更新/项目中心/首页）**必须从标题栏下方开始**：
  root 选择器挂进 `34-v046-visual.css` 的 `.app > .*` 表里，靠 flex 分配剩余高度，
  不许再写 `position:absolute; inset:0` 或 `height:100vh`。

## 9. 动效

这轮的范围（用户明确）：**只补缺失的过渡**，全局动效体系重做大改留给下一轮。

- 允许补：右侧面板页签切换、区块折叠、属性行增删、抽屉手势；
- 统一走 `--dur-*` / `--ease-*` token，不写裸 ms（系统"减少动态效果"时 token 归零）；
- **打断动画**（抽屉/弹窗反向操作）必须从当前状态继续，不许跳回起点；
- 不允许"永远循环"的动画，除非它表达"正在忙"。
