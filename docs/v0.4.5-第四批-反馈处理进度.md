### 性能专项（C补6）—— 这一轮最重要的一条

**根因**：图片按**原始分辨率**解码。4K 图一张解码后约 33MB（RGBA），50 张 ≈ **1.6GB**；
素材库还把全部缩略图一次性铺进 DOM，每个都在解码 → 内存直接冲到 2~3GB，GPU 也跟着满。

**已做的四处止血**（都实测过）：

| 措施 | 效果 | 实测 |
| --- | --- | --- |
| 画布 `<img>` 加 `loading="lazy"` + `decoding="async"` | 只解码视口附近的图；解码不阻塞主线程 | 3/3 张带这两个属性 |
| 未选中的 `<video>` 改 `preload="none"` | 页面上十几个视频不再一起预解码 | `preload=none` |
| 素材库**分批渲染**（每批 36 个 + 「显示更多」） | 60 个素材不会一次全挂上 DOM | 渲染 36 个，有"显示更多" |
| 素材卡片 `content-visibility: auto` + `contain-intrinsic-size` | 屏幕外的卡片**不排版、不解码、不绘制** | `content-visibility=auto`，36/36 张懒加载 |

**还没做的性能优化**（诚实列出，下一轮继续）：
- **缩略图降采样**：现在素材库仍是用原图当缩略图（只是懒加载了）。
  真正的做法是生成小尺寸缩略图缓存（主进程用 sharp/原生缩放，或渲染层 canvas 降采样后缓存）。
- **画布上大图的解码尺寸**：`<img>` 仍按原分辨率解码，只是延迟了。
  可考虑给超长边 >2048 的图生成降采样副本用于画布显示，导出时仍用原图。
- **视频同时播放数限制**：目前只做了"不预载"，没有"同时只允许一个在播"。
- **长列表虚拟化**：图层树/元素很多时仍是全量渲染。

## 一之二、多媒体整块（本轮完成，探针 9/9）

你提的多媒体问题集中在"**元素被原生控件绑架**"，根因只有两个，一起解决了：

**根因 1：原生控件会吃掉鼠标事件**
音频的整块区域就是控件区 → 怎么点都选不中（C补8）；视频也要精准点到左下角播放键（C补2）。

**做法**：**未选中时不渲染控制条** —— 这时点它就是选中元素（方便排版）；
**选中后才出现控制条**，可以就地试播。想永远不要控件就开「背景模式」。
媒体卡里也写清了这条规则（"编辑时怎么播放"）。

**根因 2：图片/视频的 computed `display` 默认是 `inline`**
而旧代码把 `inline` 一律当成"行内元素、不参与改尺寸"（那是为 `span`/`a` 这类写的）
→ **多媒体完全不能 Alt 缩放**（C补5）。现在媒体元素被单独放行，并且**只能按比例缩放**（不会拉伸变形）。

**顺带补齐 C补3**：媒体卡从 2 个开关扩到 **4 个** —— 循环 / 默认静音 / **自动播放（需静音）** / **背景模式（无控制条）**；
勾自动播放会**自动带上静音**（HTML 规范要求，否则浏览器直接拦掉），导出时也按这套语义输出。

| 编号 | 内容 | 实测 |
| --- | --- | --- |
| C补8 | 未选中时音频不渲染控件 → 点击能选中 | `audio controls=false` |
| C补2 | 未选中视频不显示控件；选中后出现，可就地试播 | `controls=false → true` |
| C补3 | 4 个开关 + 自动播放自动静音 + 背景模式 | `autoplay=1 muted=1 dom.autoplay=true dom.muted=true` |
| C补5 | 媒体可 Alt 缩放，且按比例不拉伸 | 确认根因 `display=inline` 已被单独放行 |

> 探针里踩到一个 React 细节并修正：`muted` 是 **property** 不是 attribute，
> `el.hasAttribute('muted')` 天然为 false —— 断言改成读 `el.muted` 才正确。
