## 一、三色 Logo 的实测参数（不是"凭感觉"写的）

原 `src/renderer/assets/logo-512.png` 用 Pillow 逐像素量取（`python tools/render-icons.py --measure <png>` 可复现）：

**色值**（三种不透明颜色各 32352 px，RGB 完全一致 → 纯色、无渐变、无描边）

| 位置 | 代表 | 色值 | RGB |
|---|---|---|---|
| 左上 | CSS 蓝 | `#2965F1` | (41, 101, 241) |
| 左下 | HTML 橙 | `#E34F26` | (227, 79, 38) |
| 右下 | JS 黄 | `#F7DF1E` | (247, 223, 30) |

**几何**（256 单位空间；512px 图上量到的包围盒换算而来）

| 位置 | 包围盒（256 空间） | 尺寸 | 圆角 |
|---|---|---|---|
| 左上 蓝 | (29, 29) → (121, 121) | 92 × 92 | 20 |
| 左下 橙 | (29, 135) → (121, 227) | 92 × 92 | 20 |
| 右下 黄 | (135, 135) → (227, 227) | 92 × 92 | 20 |

- 块间隙 = 135 − 121 = **14**；画布外边距 = **29**；三块整体 198 × 198，居中于 256 画布。
- 圆角半径由顶行扫描轮廓做最小二乘拟合得到：512px 图上 **40px → 20 单位**。
- **实测更正**：常被描述成"蓝色块更大一圈"，但逐像素测量结果是**三块完全等大**（各 92×92、各 32352 个纯色像素）。
  本次重绘严格按照实测值重建，未放大蓝块，以保证与现有界面/图标观感一致。

## 二、重绘做法（为什么边缘锐利）

1. **超采样**：在 `size × ss` 的画布上用 `ImageDraw.rounded_rectangle` 画纯几何图形，
   `ss` 取 2 的幂且保证 `size × ss` 是 256 的整数倍 —— 于是所有坐标在超采样网格上**都是整数**，
   没有半像素误差。
2. **缩小时用面积平均（`Image.BOX`）而不是 LANCZOS**：坐标既然落在整数格上，面积平均得到的就是
   **精确覆盖率**。实测对比：LANCZOS 有振铃，会把 16px 图里所有蓝块像素压成 alpha≤254、颜色偏 1；
   BOX 则内部保持纯色 alpha=255、边界得到正确的部分透明覆盖。同样的图形，`build/icon.png`
   用 BOX 后从 27.3KB 降到 12.6KB（纯色区域更干净，压缩率反而更高）。
3. **小尺寸像素对齐**：16 / 24 / 32 px 另用手调布局，块尺寸与间距都取整、左右边距严格对称，
   避免原始比例（16px 时间距只有 0.875px）糊成一团：

| 尺寸 | 块边长 | 间距 | 边距 | 圆角 | 原始等比（对照） |
|---|---|---|---|---|---|
| 16 | 6 | 2 | 1 / 1 | 1.5 | 5.75 / 0.875 |
| 24 | 8 | 2 | 3 / 3 | 2 | 8.625 / 1.3125 |
| 32 | 12 | 2 | 3 / 3 | 2.5 | 11.5 / 1.75 |
| ≥48 | 按 256 空间等比缩放（超采样 + 面积平均，边缘同样干净） | | | | |

4. **ICO 用经典 32bpp DIB 帧，不用 PNG 帧**：Windows GDI+（`System.Drawing.Icon`，也是不少旧工具的读取路径）
   读不了 PNG 压缩帧 —— 实测在 ≥64px 时报"请求的范围扩展超过了数组的结尾"。换成 DIB 帧后
   用 GDI+ 逐个尺寸 `ToBitmap()` 校验全部通过，像素颜色与 alpha 都正确。
   代价是文件变大（每个 ICO ≈ 353KB），换来的是最大兼容性。
5. **每个 ICO 尺寸都用"该尺寸专用的渲染结果"**，而不是把 256 缩下去；所以 ICO 里的 16px
   和界面用的 `logo-16.png` 是同一份像素。

## 三、`.bcproj` 项目文件图标设计思路

新设计，目标：**一眼看出"这是一个三色 Logo 的项目文件"**，且 16×16 时仍认得出三色小方块。

- **纸面**：浅色纸张 `#FFFFFF`，细边框 `#C4D0E2`，圆角；右上角沿对角线切掉一个折角，
  折角背面用更浅的 `#E4ECF6` 填充 —— 经典"文档/画板纸"的读法。
- **投影**：`#0F172A`、下移 8 单位、模糊 12 单位、不透明度 58/255，让纸面在浅色背景上也"浮"起来；
  **32px 及以下不画投影**（小尺寸下投影只会糊成一圈灰边）。
- **三色方块**：与主 Logo 相同的 L 形排列与实测色值，尺寸放大到纸面宽度的约 1/3
  （66 × 66，间距 8，圆角 15），居中于纸面 —— 比主 Logo 里的相对尺寸更大，专门为了小尺寸可辨认。
- **小尺寸降噪**：16 / 24 / 32 px 用整数像素布局（块 4/6/8px、间距 2px、边框 1px、折角 5/7/9px），
  去掉投影、折角与边框都用"先填外轮廓、再填内缩轮廓"画出精确 1px 边框，不做抗锯齿糊边。

几何参数（256 空间）：纸面 `(30,16) → (226,232)`、圆角 24、边框 8、折角 56；
方块 66×66 / 间距 8 / 圆角 15；投影下移 8 / 模糊 12 / alpha 58。

## 五、打包配置（`electron-builder.yml`）

```yaml
fileAssociations:
  - ext: bcproj
    name: BlockCanvas 项目文件
    description: BlockCanvas 积木画布项目工程文件
    icon: build/bcproj.ico
    role: Editor
    mimeType: application/x-blockcanvas-project

win:   { icon: build/icon.png }   # 实际写法为多行
mac:   { icon: build/icon.png }
linux: { icon: build/icon.png }
```

- `.bcproj` 从 v0.4.5 起是 ZIP 容器，但这里给的是自定义 mime，用于把"BlockCanvas 项目文件"
  这个身份登记给系统（Windows 注册表 / macOS 文档类型 / Linux MIME）。
- `win.icon` 从旧的 256×256 改成 1024×1024；新增 `mac.icon` / `linux.icon` 同样指向高清 PNG。

## 七、已知取舍 / 不足

- `.ico` 用 DIB 帧，体积 353KB；换成 PNG 帧能压到 14KB，但 GDI+ 读不了，故不用。
- 16px 的 `.bcproj` 图标：纸面 + 折角 + 三色小方块（4px）已经能分辨出三色，但方块确实小；
  如果以后觉得不够醒目，优先牺牲折角细节、把方块放到 5px（间距 1px）试试。
- 三块等大（实测）与"蓝色块更大"的口头描述不一致，此处以实测为准。
- macOS 只给了 PNG（electron-builder 会自行处理）；没有额外生成 `.icns`。
