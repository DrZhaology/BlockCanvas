## 一、媒体路径统一成三种写法 + 权威绝对路径（用户核心要求）

**用户原话**：
> 「视频，音频，图片现在的路径统一成 3 种：相对路径，绝对路径，URL。但是相对路径和绝对路径这个只是给人看的，真正程序设置了相对路径，一定要也记录一份绝对路径作为权威资源的路径……默认相对路径，并且相对路径加一个按钮：导出时根据位置自动匹配相对路径。」

### 为什么以前"图片预览不显示"

老的 `toRenderableSrc()` 把相对路径原样塞进 `bc-img://file/<相对路径>`，主进程只能拿几个"猜测目录"去试。工程存在别处、或者写的是 `./assets/x.png`，就猜不到 → 404 → 画布空白。

### 现在的模型：两样东西分开记

| 字段 | 用途 | 例子 |
| --- | --- | --- |
| `attrs.src` | **给人看/给人改**的写法 | `assets/bg.mp4` |
| `attrs.srcMode` | 这条写法属于哪一类 | `relative` / `absolute` / `url` |
| `attrs.srcAbs` | **权威资源路径**（唯一真相） | `D:/proj/assets/bg.mp4` |

- 画布渲染、打包进 `.bcproj`、导出时找文件，**全部只认 `srcAbs`**；
- 相对路径按"工程文件所在目录"解析（`lib/projectDir.ts`，由 `tabStore` 在新建/切换/首次保存/会话恢复时写入）；
- 工程还没保存时退回旧行为（让主进程猜），不至于直接坏。

### 新增文件

- `src/renderer/lib/mediaPath.ts` — `MediaSrcMode`、`detectSrcMode`、`toRelativeFrom`（跨盘符会返回 `crossDrive: true`）、`resolveToAbsolute`、`authoritativeSrc`。
- `src/renderer/lib/projectDir.ts` — 当前工程目录（模块级变量，不进 store，避免 Canvas 全树重渲染）。

### 媒体卡（`MediaPropsCard.tsx`）改造

- 顶部三个小标签：**相对路径 / 绝对路径 / URL**，切换时自动把当前值"翻译"成新写法；
- 输入框下面一行只读的「程序记录的实际文件」——就是 `srcAbs`，一眼看得出程序到底认哪个文件；
- 相对路径模式下多一条说明：导出时会按导出位置重算相对写法并拷文件；
- 「本地文件…」选完自动按当前模式转换（相对模式会算相对写法）。

## 二、导出改成"选文件夹" + 进任务栏 + 记住上次目录

**用户原话**：
> 「最后导出文件夹的位置要让程序拿到，然后调整。导出的时候这个过程也加入『任务』（工具栏）当中。并且程序在主动记录一下每个项目之前选择导出的文件夹，下次自动匹配。」

新 IPC `export:site`（`src/main/main.ts`）：

1. 先选**目录**（不是单个 html 文件）——这是"程序拿得到导出位置"的前提，默认值是**上次导出的目录**；
2. 收集 HTML 里所有 `bc-img://` 引用，逐个找到真实文件；
3. 拷进 `<导出目录>/assets/`（同名自动加序号），把引用重写成 `assets/<文件名>`；
4. 拷不动就退回内联 data URI（宁可文件大，也不要破图）；
5. 顺手写一份 `<工程名>.bcproj` 副本；
6. 记住这次选的目录 → `data/export-dirs.json`（按工程路径索引，未保存的用工程名）。

**任务化**：`tasks.ts` 新增 `TaskKind = 'export'` 与三个 API：

```ts
startManualTask({ kind:'export', title, detail, dest })
updateManualTask(id, { detail, pct, total, received })
finishManualTask(id, { ok, detail, error, canceled })
```

导出过程按"媒体 N/M"上报进度，工具栏「任务」按钮与任务浮层**不用改**就能显示（复用 `TaskRecord` 结构）。

## 三、position: fixed 的"两边定位基准"（用户反复提的第 4 次）

**用户原话**：
> 「position: fixed 自动使用两边（left right top bottom 其中的两边）作为定位基准没有做，现在拖动不了，这个反复提，加入任务」

### 真因（实测数据）

| 情形 | 拖动前 | 拖动后（修之前） |
| --- | --- | --- |
| `left+right`（无 width） | 849 × 60 | **60 × 60**（塌了） |
| 四边全设 | 849 × 520 | 849 × **0**（高度没了） |

一个元素如果**两边都锚着**且没写 `width`/`height`，它的尺寸是**由这两边撑出来的**。老代码拖动时只写一边、把对边清掉 → 尺寸约束消失 → 盒子塌掉。

### 修法（三处，缺一不可）

1. **双边约束的轴改成"两边一起平移"**：`left += Δ`、`right -= Δ`，尺寸严格不变；
2. **位移用指针原始增量**（`startLeft + (clientX - startX)/zoom`），不再用被"墙"夹取过的 `targetLeft` —— 墙是按"单边锚定 + 固定尺寸"推出来的，对双边元素根本不成立（实测会把元素弹到 -320px 之外）；
3. **松手时的贴边吸附跳过双边轴**（否则写 `bottom: 0` 并清掉 `top`，高度又没了）。

修完四种情形全部保持尺寸、跟手移动。

## 四、音频"点击无法选中"——查明两条 Chromium 硬约束

**用户反复反馈**：「音频根本点击无法选中」。

排查过程（每次都是实测，不是猜）：

1. 老逻辑是"控制条常显"→ 想点就选中。**实测失败**：`<audio>` 的控制条是 UA 的 shadow DOM，指针事件被控件内部吃掉，`click` 根本没派发到宿主元素（点击中心后 `selectedId` 仍是 `null`）。
2. 改成"未选中不挂 controls + CSS 占位块"。**实测仍然失败**：Chromium UA 样式表里有
   ```css
   audio:not([controls]) { display: none !important }
   ```
   而 **UA 的 `!important` 优先级高于作者样式**（层叠顺序：author `!important` < user `!important` < UA `!important`），所以没有 controls 的 `<audio>` 永远 `display:none`（实测 0×0）。
3. 最终方案：编辑器给音频套一层**自己的外壳** `<span class="bc-audio-slot">`
   - 未选中 → 外壳显示成一条「♪ 音频」占位条（看得见、点得中，就是普通元素点击）；
   - 已选中 → 外壳里才露出真正的 `<audio controls>` 试听。
   - 导出仍然只有 `<audio>`（exporter 按 node 生成，不认识这个外壳）。

> ⚠ 踩坑记录：这个分支第一版**放在 `SELF_CLOSING_TAGS` 里面**，而 `audio` 并不在那个集合里
> （那里只有 `img / input / hr / br`），所以整段是死代码、永远不执行。现已移到"容器型 return"之前。

## 五、媒体播放锁：定格帧 + 音频可见

**用户原话**：
> 「点一下，然后视频锁死，永远不会触发播放，同时如果点之前视频正在播放，就关闭。并且锁死后显示视频的第 30 帧（或者别的帧），用来体现这是视频，但是现在锁死后完全白色了。」

- **变白的原因**：锁死时给了 `preload="none"` 且不挂控件 —— 浏览器手里一帧数据都没有。
- 现在：`preload="metadata"`，加载到元数据后**定位到第 30 帧**（30fps ≈ 1 秒；短视频取 20% 处），暂停；`onSeeked / onPlay / onPlaying` 一律按回去。
- **点锁死的瞬间如果正在播**：只改 props 不会暂停（实测 `paused: false, t: 2.73`），所以加了一个 `useEffect` 直接对 DOM 调 `pause()`。
- 音频锁死后保留控制条（否则整块空白），并且仍然可见。

## 六、图片比例规则（按用户第二次澄清重做）

**用户原话**：
> 「默认从下方插入的 img 元素不要限制比例！并且我从素材插入的图片比例完全不会，被限制死了。我是说从素材插入的图片或者 img 元素设置了图片路径，那么从画布上你就不要让图片比例能修改！」

规则改成：

| 元素 | 能否自由改宽高 |
| --- | --- |
| `img`（**没有** src，纯占位） | ✅ 可以（不再锁比例） |
| `img`（**有** src） | ❌ 锁比例 |
| `video`（有 src） | ❌ 锁比例 |
| `audio` | 不涉及 |

并且"有 src 的图片"在解码完成后会**自动把外框校成真实宽高比**（偏差 > 2% 才写一次），否则插入素材后固定成 200×120、图片被拉变形，再叠上"锁比例"就是"比例完全不对还被锁死"。

## 十、属性卡片删除后的横向滚动条

**用户原话**：「css 样式属性里面的属性卡片删除后，下方会短暂出现可以左右滑动的条，修一下，不出现也滑动不了。」

原因：卡片退场动画是 `translateX(calc(100% + 40px))`，会真的把卡片推到容器右侧外面，动画期间容器短暂横向溢出。

修法：`.props-list / .inspector-sec-body / .tab-body .panel { overflow-x: clip }`（`clip` 不创建滚动容器，比 `hidden` 更彻底），并对不支持的内核退回 `hidden`。

## 十一、提示条居中

**用户原话**：「红色的提示放到正中间，现在偏左，歪了。」

`left: 50% + translateX(-50%)` 依赖"自己是相对视口定位的 fixed"；一旦某个祖先有 `transform / filter / contain`，居中基准就从"整个窗口"变成"那个容器"。改成 `left: 0; right: 0` + 内容居中 + `text-align: center`，不依赖任何百分比位移。

## 十二、视频误判为"解码不了"

**用户原话**：「我的一个 mp4 明明正常播放下方还红色提示解码不了，退回默认壁纸。」

老实现把"探测超时"也当成"解不了"（4 秒没 metadata 就判死）。大一点的 mp4 走自定义协议光读 metadata 就要几秒 —— 一个**完全正常**的视频被误判、拉黑、还弹红字。

现在区分三种结果：

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| `ok` | 有 metadata | 正常套用 |
| `timeout` | 只是**慢** | **不拉黑、不换壁纸**，继续加载 |
| `unsupported` | 明确 `MEDIA_ERR_DECODE` / `MEDIA_ERR_SRC_NOT_SUPPORTED` | 才拦下并说明"导出后在浏览器里仍可正常播放" |

`onError` 里同样只对真正的解码/格式错误拉黑；网络中断、临时读不到一律不算坏。

> `ffmpeg_common.cc Unsupported pixel format: -1` 这条日志来自原生解码器，JS 无法屏蔽 ——
> 已记入后续任务（需要换解码路径或改用不受支持的编码提示）。

## 十三、性能：最小化/静默到后台后 CPU 不下降（部分处理）

**用户原话**：
> 「有时候我可能加载了一些图片，导致 CPU 利用率上升，但是我都最小化或者都静默到后台了，这个 CPU 利用率下不来。后续把优化性能列入任务列表。」

本批先做**当下就能见效**的那一半：

- `animGovernor` 新增 `<html data-bc-window-hidden="1">`，与 `data-bc-anim-paused` **分开**：
  - `anim-paused` = "不可见 **或** 只是失焦" → 只暂停我们自己的几个装饰动画；
  - `window-hidden` = "**真的**最小化/切走"（`document.hidden`）→ 停掉页面里**所有**无限循环动画与过渡（含插件 / 用户自定义的）。
- 例外：`.tb-spin` 保持运行（下载/更新任务转圈要照常）。

**完整性能优化仍列为后续任务**（图片解码峰值、合成器层数、后台 rAF 循环审计）。

## 十四、测试窗口不再抢前台（最终方案）

用户三次反馈后确定的方案（前面几版都不对，已记在文档里）：

| 版本 | 做法 | 结果 |
| --- | --- | --- |
| 1 | `showInactive()` | 不抢焦点，但窗口**仍盖在屏幕上** |
| 2 | `focusable: false`（WS_EX_NOACTIVATE） | 真不抢了，但**最小化按钮失效** |
| 3 | `minimize()` | 不打扰，但 Chromium **暂停渲染** → 截图空白、rAF 停摆 |
| **4（采用）** | `showInactive()` + `setPosition(-32000,-32000)` + 三个 Chromium 开关 | 屏幕上什么都不出现、渲染照常、最小化可用 |

三个开关（仅安静模式加）：
```ts
app.commandLine.appendSwitch('disable-backgrounding-occluded-windows');
app.commandLine.appendSwitch('disable-renderer-backgrounding');
app.commandLine.appendSwitch('disable-background-timer-throttling');
```

配套：`nextFrame.ts`（rAF + 32ms 定时器兜底）替换了加载页淡出、切标签、面板展开里所有裸 `requestAnimationFrame` —— 否则窗口一被判定隐藏，加载页会永远挡在最上层（这是真 BUG，用户最小化着等启动就会遇到）。

正常双击启动（没有 `BC_NO_FOCUS`）行为完全不变。

## 十五、探针运行器

`pnpm test:probe` 以前是几十个 `&&` 串起来的：**一个失败就全停**，而且 Windows 上偶发 exit 2（上一条 Electron 刚退出、临时目录还锁着）。

现在 `tests/e2e/run-probes.mjs`：

- 逐个跑、**全部跑完**再汇总；
- 非 0 退出**重试一次**，重试通过标 `PASS*`（诚实标注，不静默吞掉）；
- 两次都失败才算 FAIL，并打印该探针最后 25 行输出；
- 末尾汇总表（每项 `通过数/总数` + 耗时）+ 总耗时；
- `pnpm test:probe` = 带重试；`pnpm test:probe:once` = 不重试；`node tests/e2e/run-probes.mjs batch8` = 只跑名字含 batch8 的。
