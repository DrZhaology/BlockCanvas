## 一、A5 文档搜索：关键词**黄色荧光笔** + 定位偏差

**用户原话**：「文档搜索关键词要黄色标记背景，现在只有一个淡入」+「定位有偏差」。

查下来是两件独立的事：

1. **"只有淡入"的真相**：以前跳转时确实给标题加了 `.bc-doc-hit` 类，但**这个类全仓库没有写样式**
   （只有 `.hc-hit` 有黄底）。所以浏览器只看到了一次重排，视觉上就是"闪一下淡入"。
2. **定位偏差的真相**：落点用 `el.offsetTop` 计算，而 `offsetTop` 是相对**最近的定位祖先**
   （offsetParent）—— 文档根里只要有一层 `position:relative`，整段落点就会偏。

**修法**：

- 落点改用两个 `getBoundingClientRect()` 的差值（与定位祖先无关），并让标题落在容器中心偏上；
- 标题：整行铺荧光笔黄 + 左侧一条荧光色条 + 3.2s 渐变收束；
- 小节正文：把**关键词逐处**包成 `<mark class="hc-hit">`（与搜索框内高亮同一套视觉），
  第一个命中再"跳"两下（`is-focus`）；
- 首页搜索会把当时的搜索词一起带过去（`bc:open-help-doc` 的 `q`），
  否则帮助中心不知道该标什么；
- 幂等：反复跳转不会产生嵌套 `<mark>`。

探针 `probe-v045-docmark.mjs`（9/9）：标题黄底、左侧色条、正文关键词 `<mark>`、
落点在可视区、`flashTop` 不贴边、无嵌套 mark。

## 二、J 只读快照：**只剩右侧一张面板**

**用户原话**：「只读快照面板：只保留右侧那一个面板，把所有文字都并进去，去掉下面那条栏，
面板宽度不要记忆。」

以前同一件事说了三遍：顶部 `SnapshotBar`（信息 + 三个按钮）、左侧 `SnapshotNotice`（又一段说明）、
右侧 `SnapshotInfoPanel`（再一份信息）。

现在：

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| 顶部 | 一整条快照工具条（占一行高度） | **不渲染**，只留项目标签栏 |
| 左侧 | 只读说明块 | **整块不渲染**（快照不能改内容，空面板只会挤画布） |
| 右侧 | 快照信息 + 一句提示 | **唯一面板**：徽章 / 工程名 / 时间 / 三个统计 / 三个动作 / 四段说明 / 可折叠的路径 |
| 宽度 | 沿用用户拖过的编辑器宽度 | **固定 372px，不读写 localStorage**；退出预览后编辑器宽度原样恢复 |
| 拖手 | 有（拖了也不保存） | 只读时**不给拖手** |

探针 `probe-v045-snapshot-ui.mjs`（13/13）：无顶部条、无左侧面板、无旧说明块、
右侧唯一面板含 3 个动作、宽度固定 372、无拖手、退出后布局与宽度全部恢复。

同批还把「外部」到底是什么意思讲清楚了（项目中心表头常显「?『外部』是什么？」+ 徽章 tooltip
写清"文件在你自己放的位置 / 移走就会显示文件已丢失"）。

## 三、素材缩略图**磁盘缓存**（性能）

**用户原话**：「现在动不动一个视频占用很大的内容，要优化」「素材库首屏还是会卡」。

素材库网格以前直接 `<img src="bc-img://asset/...">` 加载**原图**：
50 张 4K 图 = 50 次全尺寸解码（每张约 33MB RGBA），一进素材页就吃掉 1.5GB+，
而网格里每格只显示 62px 高。

现在：

- 主进程用 `nativeImage` 生成 **256px JPEG**，存到 `data/cache/thumbs/<name>.256.jpg`；
- 列表接口返回 `thumbUrl`（`bc-img://asset/<name>?thumb=256`），协议层直接吐缩略图字节；
- 只生成一次（内容哈希命名 → 原图变了名字就变了，天然不会过期）；
- **生成失败一律回退原图**（损坏文件 / 不支持格式），绝不让素材"消失"；
- 原图本来就 ≤256px 时不生成（直接用原图更清晰）；
- 存储面板新增「素材缩略图缓存」分类（可清理，清完再打开素材页会自动重建）。

实测：原图 272772 B → 缩略图 16974 B（**6.2%**）。
探针 `probe-v045-thumbs.mjs`（10/10）覆盖：地址带 `?thumb`、文件落盘、体积比、
网格真的用缩略图、缩略图能解码（有真实尺寸）、存储分类、清理后素材不少、清理后能重建。
