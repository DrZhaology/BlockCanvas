# BlockCanvas 扩展规范（阶段3・第二批）

> 阶段 3 分批落地：3-1 CSS 类名化（已交付）→ 3-2 扩展目录与加载入口（本批交付）→ 3-3 插件执行 → 3-4 真响应式。

## 总纲

- **扩展一律放在程序目录下**（不放用户目录/AppData），保证绿色便携、随程序移动。
- 扩展根目录 = 程序目录下的 `extensions\`，固定两个子目录：
  - `extensions\plugins\<id>\` —— 插件：改界面、改行为（**3-3 起执行**，本批只扫描识别）。
  - `extensions\resources\<id>\` —— 资源包：模板库等纯数据（本批已可加载）。
- 因此：**程序应装在本机磁盘任意可写目录**（如 `E:\BlockCanvas`、用户文件夹下某目录），不要装在 `Program Files`（那里没有写权限）。
- 运行时通过 `app.getAppPath()\extensions` 定位（主进程 `extRoot()`，见 `src\main\main.ts`）。

## 资源包（Resource）规范

资源包 = 一组**只读数据文件**，通过清单声明；渲染进程可读取并导入画布。

### manifest.json（必填）

```json
{
  "id": "showcase-templates",
  "type": "resource",
  "name": "内置新手模板包",
  "version": "1.0.0",
  "author": "BlockCanvas",
  "description": "新手模板：直接插入整段已排好版的区块",
  "templates": [
    { "id": "landing-hero", "name": "首页大标题区", "description": "深色大标题 + 主按钮的首页首屏" }
  ]
}
```

- `id` 必须与目录名一致（`extensions\resources\showcase-templates\`），不一致会被扫描器标记为错误。
- `templates[]` 中的每项对应 `templates/<id>.json`。

### 模板文件（templates/<id>.json）

即一棵 `SceneElement` 树的 JSON 快照（与 `types.ts` 的元素结构一致：`id/type/text/children/style/attrs`）。

#### 编写硬性要求（v1.1 起）

1. **每个元素都必须带 CSS 选择器**：`attrs.className`（首选，语义化命名）或 `attrs.id`。
   裸元素插入画布会立刻触发"未命名"⚠ 警告，属于不合格模板。
   命名建议：`区块用途-角色`（如 `hero-title / card-text / nav-link`），多个类名空格分隔。
2. **选择器要写清楚、可读**：自动生成的 `<style>` 会直接使用这些名字（`.hero-title { … }`），
   它们就是导出代码的一部分——按"别人会读你 HTML"的标准起名。
3. **鼓励使用关系选择器（childStyles）**：容器上声明"里面的某类子元素"的公共样式，
   避免给每个子元素重复写一份。字段挂在任意元素节点上：

```json
{
  "type": "section",
  "attrs": { "className": "cards-row" },
  "childStyles": [
    { "sel": ".card",       "css": "flex: 1 1 0px; box-sizing: border-box;" },
    { "sel": ".card-title", "css": "margin: 0 0 8px; font-size: 18px; color: #111827;" },
    { "sel": "p",           "css": "line-height: 1.7;" }
  ]
}
```

   - 导出规则形如 `.cards-row .card-title { … }`（后代选择器）；`sel` 支持 标签 /
     .类名 / #id 组合，空格 = 后代、`>` = 直接子级；也支持伪类（如 `.nav-link:hover`）。
   - 禁止逗号多选择器与属性/通配等进阶语法（程序会跳过不合法项）。
   - 最佳实践：**公共样式上移到容器 childStyles，个性差异留在子元素自己的 style 里**
     （参考内置 footer：p 的居中行高在容器上，两个 p 的颜色字号各自保留）。

4. 元素自身 `style` 与 `childStyles` 同时存在时，关系规则的特异性更高，
   子元素自己 style 写在同属性的值会被它覆盖——想覆盖请选中子元素改它的规则或加专属类。

### 插入行为

导入画布时（`sceneStore.insertTemplate`）：

- 整棵树所有 `id` **重新生成**（uuid），可无限次插入、不会与画布已有元素冲突；
- 作为子树插入**当前选中容器的内部**（未选中则插入画布根）；
- 插入动作进入撤销历史，Ctrl+Z 可整体撤销。

## 插件（Plugin）规范（3-3 已落地）

- 清单为 `manifest.json`，字段：`id / type:'plugin' / name / version / author / description / main`。
- `main` 指向插件入口 JS 文件（相对插件目录）。

### 执行机制（插件兼容程序，不是程序兼容插件）

- 程序**不加载 CommonJS / ESM 模块**，只把 `main` 入口文件以**源码字符串**下发给渲染进程，
  渲染进程用 `new Function('Bc', source)(Bc)` 求值（CSP 已开 `unsafe-eval`）。
- 因此插件入口是一个**立即执行函数** `(function (Bc) { ... })(Bc)`，`Bc` 是程序提供的宿主对象。
- 每个插件拿到**独立的 Bc**（绑定自身 id），不注入全局变量、不暴露程序内部对象。

### 宿主对象 Bc（稳定接口）

| 方法 | 说明 |
| --- | --- |
| `Bc.onStart(cb)` | 注册启动回调（样式注入、监听器等都放这里） |
| `Bc.onStop(cb)` | 注册卸载回调（清监听、删样式），插件被禁用/删除/重载时统一调用 |
| `Bc.registerCss(css)` | 注入全局 `<style>`，返回一个卸载函数（调用后移除样式） |
| `Bc.registerCommand({id,label|(fn),icon,title,onClick})` | 在工具栏注册一个命令按钮，自动进「动态工具栏」 |
| `Bc.api` | 程序原生 `window.bc`（导出/预览/模板等 IPC），插件可透传使用 |
| `Bc.log(...args)` | 带插件前缀的控制台日志 |

- `label` 传函数时每次渲染自动取最新返回值，可做动态文案（如显示当前模式）。
- 插件命令的 id 会被自动加上 `plg.<插件id>.` 前缀，进入与内建按钮同一套「可拖拽 / 可固定 / 自适应折叠」机制，默认进「更多」菜单（不占空间）。

### 主题/样式约定

- 程序主题靠 CSS 变量（`--bg / --bg-panel / --bg-canvas / --border / --text / --text-muted / --accent` 等）驱动，插件通过 `registerCss` 覆盖这些变量即可深度换肤，无需改动程序结构。
- 参考实现的 `extensions\plugins\dark-mode\`：用 `html[data-bc-dark]` 标记深色生效，监听 `matchMedia('(prefers-color-scheme: dark)')` 跟随系统，工具栏按钮可手动切 自动/深色/浅色，选择存 localStorage。

### 生命周期与刷新

- 应用启动时、以及扩展管理页里对插件「启用 / 禁用 / 导入 / 删除」后，渲染进程派发 `bc:plugins-changed` 事件，`pluginHost.refreshPlugins()` 先 `stop` 全部旧插件、清掉它们注册的工具栏项，再按 scan 结果重新执行所有「已启用」插件。

## 插件导入（3-3）

- 扩展管理页插件区支持：**导入插件文件夹**（`ext:import-folder`，整目录含 manifest 拷入 `extensions\plugins\<id>\`）与**导入 zip 插件包**（`ext:import-zip`，解包同名结构）。
- zip 内应为 `manifest.json + 入口文件 + 附属文件`，可带或不带顶层 `<id>` 文件夹。
- 导入后立即 `pluginsChanged()` 刷新宿主，插件即刻生效。

## 目录结构速查

```
程序目录\
├─ app（或 asar）
├─ extensions\
│  ├─ plugins\        # 插件（3-3 起执行）
│  │  └─ <id>\manifest.json
│  └─ resources\      # 资源包（本批可用）
│     └─ <id>\
│        ├─ manifest.json
│        └─ templates\*.json
```

## 扫描器行为（main.ts scanExtensions）

- 只读：扫描目录 → 读每个包的 manifest.json → 校验 `type` 与所在目录一致 → 收集错误（缺清单、清单坏、id 与目录不符等）。
- 资源包额外解析 `templates[]` 清单，模板正文在用户点击时才读（`ext:read-template`）。
- 扫描结果与错误汇总进 IPC 返回，弹窗与「模板」页签共用。
