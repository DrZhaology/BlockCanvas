## 1. 属性卡片：删除退出动画（你重点强调的那条）

**改成什么了**

以前"手动点删除没动画"是三个原因叠在一起：

1. `animateRemove()` 收到的是 `e.currentTarget` —— **那颗 18×18 的 × 按钮**，
   不是卡片。`.is-removing` 挂在一个透明小按钮上，卡片本体一动不动；
2. 就算挂对了，CSS 只动 transform / opacity、**不收高度**：
   卡片滑出去时还占着原来那块高度，340ms 后节点被删，下面的卡片"啪"地跳上来 ——
   你要的"别的卡片把退出的空位补上"根本没发生；
3. 这期间只要 React 重渲染一次，`classList.add` 的类会被整个 className 重算覆盖掉。

现在：`PropertyRow` 把**卡片自己的根节点**交给父级；父级在加类**之前**量出真实高度写成
`--bc-row-h`，再用 state 控制 `.is-removing`（React 保证类一直在）。

**动画本身（按你的第 3 条）**

| 阶段 | 变化 |
| --- | --- |
| 0 → 28% | `scale 1 → 0.966`，阴影从无涨到 `0 10px 24px rgba(20,40,80,.18)` —— 就是你说的"向后缩、浮起来"那股劲 |
| 28% → 100% | 带着阴影往右滑 92px、再缩到 0.94、淡出，**同时高度从真实值收到 0** |

高度是整段一起收的，所以下面的卡片是**平滑往上补位**，不是最后跳一下。
（探针实测：60px → 19px → 16px → 0）

**怎么验**

1. 选中一个元素 → 右侧「CSS 样式属性」→ 加两条属性（比如「字间距」「图层层级」）；
2. 点其中一条右侧的 × → 应该看到：**先轻微缩小、阴影浮起来 → 向右滑出 → 下面的卡片顶上来**；
3. 同一条删完立刻 `Ctrl+Z` → 卡片从**右边滑回来**，其它卡片让开；
4. 再 `Ctrl+Y` → 卡片按同一套退场动画走掉。

硬证据：`node tests/e2e/probe-prop-card-anim.mjs` → **25/25 通过**
（其中 ②卡片本体带 `is-removing`、③中段 `scale(0.966)` + 阴影 `0 10px 24px`、
③末段 `translateX(92px)` 且 `height: 0`、③b 340ms 后行真的消失且无骨架残留、
④ Ctrl+Z 拿到 `propCardIn`、Ctrl+Y 出现骨架退场）

## 2. 新增卡片：只闪一下，不再有「新」字样

- 「新」徽标（`.prop-new-badge`）**已彻底删除**，界面上不会再出现这个字；
- 新加的行 = 从右边滑入（`translateX 56px → 0`，280ms）+ 底色闪两下，
  形状、边框、底色和其它行**完全一样**；
- 类别不再靠"每条一套彩底 + 深色竖杠"区分（那正是"不统一"的来源），
  只体现在**标题文字颜色**上。

**怎么验**：连着加 3 条属性，看它们落地后和其它行长得是否一致；趁动画那 280ms 看一眼是从右边进的。

## 4. 定位助手：`position: relative` 偏移量不显示（真 BUG，已修）

真因：`.pos-edges` 是**两列网格**（为 `absolute/fixed` 的四条边设计），
而 `relative` 只渲染**一行**（偏移量 + left/top 两个数字框）——
它被塞进**半格宽**的网格单元，两个 `num-unit-row` 各分到几十像素，
数字框宽度被压到 0，屏幕上就是"整块消失"。

现在：`.pos-edges > :only-child { grid-column: 1 / -1 }`（只命中 relative 的单行 / sticky 的单块），
标签宽度收窄到 62px，数字框各拿 62px；`absolute` 的四行布局一点没动。

**怎么验**：选中元素 → 快捷助手 → 定位助手 → 把定位改成 `relative` →
「偏移量」那一行应该有 **左 / 上 两个能输入的数字框**（各 62px 宽）。
`sticky` 应看到「吸附方向（吸顶/吸底）+ 距边多少」。

硬证据：`node tests/e2e/probe-pos-helper.mjs` → **11/11 通过**
（含 `line=412 / edges=412` 说明跨满整行、两个输入框 62×26、输入 24 后 `left=24px`）

## 5. 页面背景色支持渐变

- 「页面」页签 → body 设置 → **页面背景** 现在是 `纯色 / 渐变` 两段式；
- 渐变复用元素那一套编辑器（角度盘、色标、预制配色）；
- 两个字段分工：`bodyBg` 写 `background-color`，新增的 `bodyBgImage` 写 `background-image`
  —— 可以叠着用（半透明渐变 + 底下垫纯色）；
- 导出与画布同源（`quickCssToCss` 一起输出），旧工程完全兼容。

**怎么验**：页面页签 → 点「渐变」→ 调一下角度/色标 → 画布和「预览」应该同时变；
再切回「纯色」→ 渐变消失、纯色还在。

## 6. 导出前体检：误报 + 不再拦预览

**误报（你说"我正常做怎么还是有问题"）**

以前只要两个元素写了同一条 `relSelector` 就报 critical「关系选择器被多个元素共用」。
可这本来就是我们鼓励的用法 —— 一批同类子元素共享一条关系选择器，导出的 CSS 只有一条规则。
真正会出事的只有 v0.4.4 那个场景：**两张互不相干的表用了同一个类名**，
它们同位置的格子算出一样的选择器 → 改表 A，表 B 跟着变。

判据已收紧为「同一选择器被**分属不同表格**的元素共用」。
探针实测：造两个普通兄弟元素写同一条关系选择器 → 体检**不再报**这条，只剩原本的「元素没有类名」。

**预览不再被拦**

`doPreview = () => previewNow()`（去掉了体检闸门）；`doExport` 仍然先体检。
理由：预览不改任何文件，却是高频动作；被一张红牌挡住去点掉，代价远大于收益。

**怎么验**：随便做个有严重项的页面 → 点「预览」应**直接出**；
点「导出 HTML」仍会先弹体检向导。⚠ 按钮本身一直在，想体检随时点。

## 7. 选中框：橙框 + 呼吸闪烁（≤5 个）/ 只描边（>5 个）

| 选中数量 | 表现 |
| --- | --- |
| 1 ~ 5 | 2px 橙框 + **呼吸光晕**（1.1s 周期，只动 filter，合成层动画） |
| > 5 | 只留 2px 橙框，**不加任何动画**（防止一屏十几个元素同时跑动画掉帧） |

- 数量写在根节点 `data-bc-seln`（1 = 闪烁档，0 = 仅边框档）；
- 行内元素的合并外框（`.canvas-inline-sel`）跟同一套节奏；
- 按住 Alt 时橙框让位（那时看的是 Alt 悬停/拖动框）；
- 设置里若选了「蓝色细线」档（`body.bc-sel-plain`），仍然尊重它、不闪；
- 系统开「减少动态效果」时不闪，只留框。

**怎么验**：单击选中一个元素 → 应该在呼吸；框选 6 个以上 → 全部静止只剩橙框。
