# BlockCanvas 积木画布 · 功能规划

> 项目名：**BlockCanvas**（英文）/ **积木画布**（中文）
> 项目类型：可视化静态网页构建工具（所见即所得），后期接入 Scratch 式积木编程
> 目标平台：Windows（本期），后续可扩展
> 最后更新：2026-08-26

---

## 一、项目简介

一个让**完全不懂代码的人**也能做出专业网页的桌面应用：

- 用鼠标拖拖拽拽画界面，像画图软件一样
- 内置大量模板，一键插入
- 后期用 Scratch 式积木编程加交互（按钮点击、动画、表单逻辑…）
- 最终导出干净的、可读的 HTML + CSS（+ 后期 JS）文件

**一句话定位**：给零基础用户的「可视化网页工厂」，产物必须是手写级的干净代码，不是石山。

---

## 二、设计原则

1. **产物优先**：导出的 HTML/CSS 要像人手写的一样语义化、整洁、可维护。绝不为了开发方便就导出一堆 `<div>` 山。
2. **对小白友好**：UI 用中文按钮和提示，隐藏 CSS 术语（flex/盒模型…）在通俗表达背后。
3. **流式布局为王**：默认走文档流，贴合真实网页行为；只在用户主动切换 CSS `position` 后才允许自由拖动。
4. **可撤销可恢复**：所有操作都进 Undo/Redo 栈，从第一天就把状态设计成可序列化的单一数据源。
5. **分阶段、小步快跑**：先跑通「拖一个元素 → 改样式 → 导出 HTML」最小链路，再逐步加功能。

## 四、核心技术决策（已确认）

| 决策点 | 结论 | 影响 |
|---|---|---|
| 布局模式 | 流式布局为主；每个元素可切换 CSS `position`（static/relative/absolute/fixed/sticky）；只有 `absolute`/`fixed` 时才在画布上自由拖动+定位坐标 | 难度高但产物是手写级 CSS |
| Flex 暴露方式 | 封装成中文「横排容器 / 竖排卡片」按钮+对齐方式选项；背面生成干净 `display:flex` 代码 | 小白用得了，产物专业 |
| 目标用户 | 完全不懂代码的人 | UI 必须傻瓜化 + 内置提示/教程 |
| 代码编辑器引入时机 | 第一期**不做**；后期加**只读代码视图**；最后才做可编辑回写 | 降低早期复杂度 |
| UI 风格 | Windows 亮色原生风格，Segoe UI；**不做深浅切换**（长期也不做） | 减少视觉维护成本 |
| 缓存位置 | 全部迁至 `E:\Develop\DevCache\{npm,pnpm,electron}` | 保护 C 盘 |

## 六、分阶段开发计划

> 每阶段都有明确可验证的交付物，跑不通不进下一阶段。

- [ ] 一块空白画布

### 阶段 1：HTML 结构系统
- [ ] 完整元素面板：容器/div/section/header/nav/footer/标题/段落/图片/按钮/链接/输入框/分割线

- [ ] 图层树（右侧）：反映 DOM 嵌套，拖拽改层级/重命名/显隐/锁定
- [ ] 元素增删改：删除/复制/粘贴/撤销

## 七、难点预警（Risk Register）

| # | 难点 | 影响 | 缓解策略 |
|---|---|---|---|
| R1 | 拖拽命中 + 坐标变换（画布缩放/滚动） | 高 | 阶段0先在固定缩放下跑通；缩放放阶段4 |
| R2 | 流式布局 + 自由拖动混用 | 高 | 流式只做 reorder；absolute/fixed 才做 transform/top-left 拖动 |
| R3 | Undo/Redo 全局状态可序列化 | 高 | 阶段0就把状态做成单一 scene graph（类似 Figma） |
| R4 | 样式类 vs 内联样式取舍 | 中 | 阶段2定基调：不改类的样式走内联，要复用才抽类 |
| R5 | Blockly 积木 → 元素 ID 绑定同步 | 高 | 元素 ID 用稳定 UUID，删除/重命名发事件让积木订阅更新 |
| R6 | 元素 ID 唯一性与稳定性 | 中 | UUID 方案，不用数组索引 |
| R7 | 导出代码质量（语义化、不堆 div） | 高 | 元素系统区分语义标签；导出器有「语义化 lint」校验 |
| R8 | Electron 体积/内存 | 中 | MVP 不管；阶段6评估 Tauri 迁移 |

## 八、术语表

- **画布（Canvas）**：所见即所得编辑区
- **元素（Element）**：画布上的一个 DOM 节点
- **Scene Graph**：整个工程的单一可序列化数据源
- **样式类（Style Class）**：可被多元素复用的 CSS 类
- **断点（Breakpoint）**：响应式宽度档位
- **积木（Block）**：Blockly 里一块图形化代码块

## 十、移动端适配方案 A（竖屏优先，待实现）

### 触发条件
- 视口宽度 < 768px 时自动切换

### 布局变化

```
顶栏（不变）：项目标签 + 工具栏图标行（压缩为单行，折叠成「⋯ 更多」）
画布区域（全屏宽度，无侧栏）
─────────────────────────────────────
浮层面板（从底部滑入，占屏幕 85% 高度）：
  ┌─────────────────────────────┐
  │ [×关闭]  [元素│模板]  [图层│属性]  │
  ├─────────────────────────────┤
  │                             │
  │   面板内容区（可滚动）       │
  │                             │
  └─────────────────────────────┘
```

### 交互变化
- 左侧面板（元素/模板）、右侧面板（图层/属性）均改为全屏浮层，从底部滑入
- 工具栏图标压缩为单行，超出部分折叠进「⋯ 更多」菜单
- 画布占满全宽，拖拽/缩放操作完全适配触摸
- 浮层面板内 Tab 切换（元素↔模板、图层↔属性）保持现有逻辑不变
- 画布缩放/拖拽改为触摸手势（双指缩放、单指拖动）

### 与桌面端关系
- 桌面端完全不受影响（`window.innerWidth >= 768` 时保持现有三栏布局）
- 布局状态通过 `localStorage['bc-layout']` 独立存储
