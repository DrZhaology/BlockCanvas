# BlockCanvas v0.4.6 发行说明

> 版本 **0.4.6** · 阶段 6 · 架构重构与 Web 版上线（正式版）
> 发布日期：2026-11-14
>
> 这一版的主线不是加功能，而是**把地基建好**：两个 2400+ 行的组件拆开、
> 上线网页版、修掉拖了三个版本的 fixed / sticky / 视频编码问题。
> 全量自动化探针从 52 个扩到 60 个。

## 一、这版最重要的三句话

1. **代码结构换了一遍**：`Canvas.tsx` 2431 → 351 行，`Inspector.tsx` 2467 → 174 行，
   都拆成"组装层 + 按职责分模块"，并有探针盯着"别再长回去"。
2. **网页版能用了**：一份单文件 HTML（约 2MB），双击就能开，能建工程、加元素、改样式、导出。
3. **三个老问题根治**：`fixed` 拖不到底、`sticky` 看不出效果、某些 mp4 一插入就白屏。

### 2.7 CSS 域约束：从"按批次命名"到"可校验"（R6-3）

这一版**没有**做一次性大搬迁（34 个文件 1.5 万行、2826 个唯一选择器，
搬完无法保证视觉零变化，而本轮底线是"探针全绿"）。做的是**把约束建立起来**：

- 新增 `src/renderer/styles/domains.ts`：34 个分片各自登记主域
  （theme / shell / canvas / inspector / element / table / overlay / empty-home / projects / settings / help）
- 新增 `probe-css-domains`（7 条断言）：
  · 每个分片必须登记主域（**新增分片忘登记会红**）
  · 登记表不许残留已删除的分片
  · 有辨识度前缀的选择器不许跑错域（`.eh-` 只在空首页、`.tbl-` 只在表格…）
  · 跨域重复选择器**不许超过基线**（当前 217 条，防新增）
  · 样式总量 < 700KB（防重复堆叠）
- 顺手修掉了实际错位：**20 条 `.eh-*` 规则从 27/29 号分片归位到空首页域**
  （它们本来就是空首页专属类名，只是当年随手追加到了"最新的那一片"）

**为什么停在"可校验"而不是合并那 217 条**：每条都要判断"后声明的哪些属性是修正、
哪些是遗留"，而**探针查不出视觉变化**（"颜色淡了一点"只能人眼）。
合并留到有足够视觉验收预算时做 —— 现在至少**不会继续变坏**。

### 2.8 防回退：结构探针重写（28 条断言）

原来的"全项目单文件 ≤700 行"试过用基线表维护，结果表越列越长
（TableEditor / Settings / sceneStore / App / EmptyHome / propertySchema / ProjectsCenter /
Icon / ElementPanel / tableOps / ColorPicker / QuickHelper / updater…），
**维护成本比收益高，而且拦不住真正的问题**。

现在的判定改成：**只盯本轮拆过的域** ——

- `canvas/` 每文件 ≤600 行、组装层 ≤400 行、纯计算层不许 import React
- `inspector/` 每文件 ≤600 行、外壳 ≤400 行、行组件不反向依赖区块组件
- `scene/` 每文件 ≤400 行、不反向依赖 `sceneStore.ts`
- `ipc/` 每文件 ≤400 行、每域都导出 `register*Ipc()`、`main.ts` ≤620 行
- `styles/domains.ts` 必须存在（CSS 域索引）

真正会出事的不是"某个历史文件大"，而是"**刚拆好的地方又长回去了**"。这些断言盯的就是后者。

## 三、网页版上线

### 3.1 怎么用

```bash
pnpm build:web        # 产出 dist-web/index.html（单文件，约 2MB）
```

产物就一个 `.html`：

- **双击打开**（`file://`）—— 工程存在浏览器的 IndexedDB 里，导出走"下载"。
- **放到静态托管**（GitHub Pages 等）—— 同一个文件，能力一样。

### 3.2 为什么能"同一个渲染层换宿主"

渲染层是纯 Web 应用（0 个文件 import `node:*` 或 `electron`），所有系统能力都走 `window.bc.*`。
所以换宿主 = 换这一层实现：

| 能力 | 桌面版 | 网页版 |
| --- | --- | --- |
| 工程存取 | 磁盘 `.bcproj` 文件 | **IndexedDB** |
| 素材 | `data/assets/` + 协议 | IndexedDB Blob |
| 导出 HTML | 写磁盘 / 导出网站文件夹 | **触发下载**（单页 `.html` 或整站 `.zip`） |
| 预览 | 系统浏览器打开 | **新标签页** |
| 自动更新 | 有 | **不适用**（刷新就是最新） |
| 插件 | 加载本地插件目录 | **不加载**（浏览器没有本地目录） |

做不到的能力会**明确返回"网页版不可用"**，不会点了没反应。

### 3.3 已知限制

- 插件系统在网页版**不工作**（没有本地目录可扫）。
- 网页版**没有自动更新**（刷新即最新）。
- `file://` 下部分浏览器会限制 IndexedDB —— Chromium 系（Edge / Chrome）正常。
- 单文件产物约 2MB，首次加载稍慢（已全内联，之后无外部请求）。

## 四、三个遗留问题根治

### 4.1 `fixed` 元素的"空气墙"（拖不到底）

**症状**：`position: fixed` 的元素往下拖，永远贴不到"首屏底部"，写不出 `bottom: 0`。

**根因**：fixed 在浏览器里相对**视口**定位，但画布高度随内容长 ——
短页面 600px、长页面 3000px，`bottom: 0` 到底指哪儿说不清。

**解法**：场景记住一个**基准视口高度**（默认 900，可在「页面」页签调）：

- 画布至少撑到这么高 —— 短页面下 `bottom: 0` 立刻有落点；
- 内容比它长时，在该高度画一条**首屏线**（虚线，不挡操作）；
- fixed 的拖动墙止步于首屏线，而且**不再跟着画布变长**。

**一个必须知道的细节**：画布自己就是 fixed 的包含块，所以长页面上 `bottom: 0`
会解析成"画布底"（几千米外）。因此**长页面上松手不会写成 `bottom: 0`**，
而是保留数值偏移（否则元素一松手就飞走）；短页面才写成 `bottom: 0`。

### 4.2 `sticky` 可视化（看不出效果）

**症状**：sticky 的效果只在页面滚动时可见，而画布本身不滚，所以编辑器和普通元素长得一样。

**解法**（把"生效条件"说清楚，不做不可信的滚动模拟）：

- 会吸附：元素角上显示「粘 距上 20px」+ 一条虚线；
- **没写 top/bottom**：角标变橙色警示色，写「粘 未设距离」——
  这是最常见的错，sticky 没偏移就**永远不会吸附**；
- 快捷助手里同步给出解释。

### 4.3 `ffmpeg Unsupported pixel format`（视频白屏）

**症状**：一个 mp4 明明能播，编辑器里却白屏，日志是
`ffmpeg_common.cc Unsupported pixel format: -1`。

**根因**：那条日志来自 **Chromium 的原生解码器**，JS 侧屏蔽不了。它触发于
"把 `<video>` 挂上去"的**瞬间** —— 只要挂了就会尝试初始化解码器。
容器里声明的编码属于 Electron 不带的那几种（**HEVC/H.265**、杜比视界、H.266）时就白屏。

**解法**：**挂之前先读容器头**：

- MP4：按盒大小跳读 `moov → stsd`，取编码四字码（`avc1` / `hvc1` / `av01`…）；
- WebM：读 `CodecID`；
- 明确解不了 → **根本不挂 `<video>`**，改画一个"视频编码不支持"占位块
  （可选中、可拖动），属性面板同时给出转换建议（含 ffmpeg 命令）；
- **读不出来就照常播放** —— 绝不因为探测失败误杀正常视频。

用 ffmpeg 生成的真素材验证过：H.264（含 moov 在尾部）判支持，HEVC（hvc1/hev1）判不支持。

## 五、插件接口（只定形状，不放能力）

这版给插件加了 **能力声明**，但**没有做真沙箱**（诚实说明）。

```jsonc
// 插件 manifest.json
{
  "apiVersion": "1",
  "permissions": ["css", "command"]
}
```

可声明 6 项能力：`element` / `property` / `export` / `command` / `css` / `hostApi`。

三条规则：

1. **没声明 `permissions`** → 只给最小集（`element` + `property`），老插件行为不变；
2. 声明了不认识的能力 → 忽略并记 warning，不阻断加载；
3. **`apiVersion` 比程序高 → 拒绝加载**并说明原因（比"跑到一半崩"好得多）。

未声明的方法在插件拿到的 `Bc` 上**根本不存在** —— 调用会直接 `TypeError`，
而不是静默改坏东西。

> ⚠ 重要：插件仍与程序**同上下文**运行（`new Function`）。这一版做的是"少给参数"，
> 不是隔离。真正的沙箱（iframe / Worker）留到后面做。

## 六、窄屏外壳（手机布局的前置）

主窗口最小宽度从 **960 放开到 360**。以前锁死，所以"编辑器自己的手机界面"这件事
**根本不存在**（不是做得不好）。

- **900px** 是外壳断点（与网页断点 768/480 无关，后者管的是被设计的那张网页）；
- 窄屏下左右面板改**抽屉**：滑入 + 遮罩，点遮罩关闭，画布占满；
- 设置页「编辑器与画布」里有**竖屏验收**：一键切到 412×915（安卓）/
  390×844（iPhone）/ 360×800（窄档）。

竖屏显示器就是现成的手机验收台 —— 能验：宽高比观感、抽屉手感、480/768 断点效果、
长页滚动性能、触摸目标是否够大（窄屏下可点元素都 ≥44×44）。
**不能验**：真机触摸事件、Android WebView 渲染差异、软键盘弹起。

## 九、升级建议

- **桌面版**：直接覆盖安装即可。工程文件格式未变（`SCHEMA_VERSION` 仍为 2）。
- **新增字段**：`scene.viewportHeight`（基准视口高度）。老工程没有这个字段时按 900 处理，
  不影响打开与导出。
- **插件作者**：建议补上 `apiVersion: "1"` 与 `permissions` 声明。
  不补也能继续用（按最小权限运行），但声明之后能用到更多能力。
- **想试网页版**：`pnpm build:web` 后双击 `dist-web/index.html`。
