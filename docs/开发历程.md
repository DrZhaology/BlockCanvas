## 2026-08-26 — 修复版本号 0.0.0 BUG + 统一版本号显示来源 + 修正打包结构

> 用户反馈：①检查更新显示 0.0.0；②zip 里还包含旧的 extensions/ 目录（已迁移至 data/extensions/）。

### 问题诊断
- `getLocalVersion()` 用 `dirname(process.execPath)` 找 `package.json`，但 Electron packaged 模式下文件在 asar 内 → 返回 `'0.0.0'`
- `electron-builder.yml` 仍把 `extensions/**` 打进包，`build-exe.ps1` 也还在复制 extensions 到 exe 旁
- 正确的便携包结构：exe 旁无 `extensions/`，`data/extensions/` 内置插件/资源包随 zip 分发，运行时种子同步

### 做了什么
1. **修复 `getLocalVersion()`**：优先用 `app.getVersion()`（Electron 内置，兼容 asar）
2. **新增 `update:get-version` IPC** + `About.tsx` / `Settings.tsx` 动态读版本
3. **移除打包里的 `extensions/`**：`electron-builder.yml` 删除 `extensions/**` 规则，`build-exe.ps1` 删除复制步骤
4. **zip 内加入 `data/extensions/`**：`build-exe.ps1` 新增步骤，把源码 `data/extensions/` 复制到 win-unpacked 后压缩
5. **新增 `seedExtensionsFromZip()`**：启动时从 zip 内的 `data/extensions/` 同步内置扩展到运行时 `data/extensions/`，同名覆盖、用户第三方扩展保留

### 自测
- `tsc --noEmit` ✓；`electron-vite build` ✓。
- `tar -tf BlockCanvas-0.3.1-win64.zip | grep data` 确认 `data/extensions/` 已在 zip 内，exe 旁无多余 `extensions/`。
- GitHub Release v0.3.1 已更新附件（旧附件已删除后重新上传）。

## 2026-08-26 — 自动更新系统 + 扩展目录统一到 data/extensions/

> 用户反馈：扩展全部移到 data/ 了，extensions/ 这个文件夹应该不用了；要求做自动更新系统。

### 做了什么
1. **扩展目录统一迁移至 `data/extensions/`**：
   - 移除原先把 `extensions/` 放在 exe 旁（只读种子 + 可写运行时）的双路径设计；
   - 从 `initDataDirectories()` 中移除 `seedBuiltinExtensions(extDir)` 调用；
   - `extRoot()` 已始终指向 `data/extensions/`，代码无侵入式改动。
2. **实现自动更新系统**：
   - **版本检测**：读本地 `package.json.version`，直连 GitHub API 获取 release 列表（含 prerelease），匹配当前平台（win32-x64）的 asset；
   - **启动自动检查**：App 启动 5 秒后静默检测，有新版本弹确认框；24h 内不重复检测（记录在 `config.json.lastCheckUpdate`）；
   - **手动检测**：设置页「自动更新」卡片 + 菜单「设置 → 检测更新…」；
   - **下载并更新**：下载 zip（通过 gh-proxy 镜像）→ 解压到临时目录 → 覆盖 appDir（精确跳过 `data/` 目录）→ 重启应用；
   - **回滚机制**：更新前备份 `appDir.bak`，失败时自动恢复。
3. **IPC 接口**：新增 `update:check`（检测结果）和 `update:apply`（执行更新）两个 IPC handle。
4. **文档同步**：更新 `.gitignore`（`data/` 忽略但保留 `extensions/` 源码）、`README.md`、`功能规划.md`。

### 自测

## 2026-08-26 — 修复缓存清理无效（只清文件不清目录）+ 按钮对齐偏移问题

> 用户反馈：①清理完缓存还是 43.94MB，说清理不掉；②运行缓存后面的「清理」按钮偏下。

### 问题诊断
- **根本原因**：`clearAppCache` 使用 `rmSync(dir, { recursive: true })` 把整个 Cache 目录整棵删除，但 Chromium 下次启动时会自动重建该目录并重新填充 41MB+ 内容；
- **修复策略**：改为「只删除目录内的文件，保留空目录壳子」，Chromium 无法再重建大量数据；
- **按钮偏移**：`.btn-secondary` 有 `margin-top: 10px; width: 100%`，被用在卡片内时导致垂直偏移和宽度异常。

### 做了什么
1. **彻底重写 `clearAppCache`（`userData.ts`）**：
   - 不再 `rmSync(dir)` 删除整目录；
   - 改为遍历每个缓存目录，**逐文件删除**（`unlinkSync`），子目录也递归清空；
   - 保留目录结构，避免 Chromium 重建大量空白 Cache 目录；
2. **修复 `.btn-secondary` 全局样式（`styles.css`）**：
   - 移除 `margin-top: 10px` 和 `width: 100%`（这两个属性只适合大表单按钮，不适合卡片内联控件）；
3. **修复卡片内按钮容器**（`Settings.tsx`）：
   - 给 `fluent-card-ctrl` 加 `flexShrink: 0; alignSelf: 'center'` 确保垂直精确居中。

### 自测
- `tsc --noEmit` ✓；`electron-vite build` ✓（css 124.89kB / js 701.14kB）。
- 客户端已重启；设置 → 存储与自动备份：点击「一键立即清理」后秒级响应；再点「刷新」后缓存读数大幅下降（只保留空壳目录，不会像之前那样被 Chromium 立即重建回 41MB）。

## 2026-08-26 — 修复删除属性时未同步同选择器元素导致的类名/ID冲突问题

> 用户反馈：如果删除一个选择器元素的一个属性，如果这个选择器还控制着别的元素，那么这个属性删除时，只会删除选中元素的这个属性，别的元素不会同步删除，显示类名ID错误。

### 做了什么
1. **深入根因分析**：
   - 当多个元素共用同一类名（如 `.card`）或同一关系选择器（如 `.hero > p`）时，修改属性会走 `syncClassmates` 自动同步；
   - 但此前在 `removeVisibleProp`（点击「×」删除属性）和 `addVisibleProp` 时，只修改了当前选中节点，未调用 `syncClassmates` 同步给同类名伙伴，导致同名类下各元素的 `style` 字段出现差异；
   - `styleClass.ts` 在收集阶段检测到同名类的属性不一致，判定为样式冲突，抛出「多个元素共用这个名称但样式不完全一致」的错误警告。
2. **底层同步全链路修复（`sceneStore.ts`、`Inspector.tsx`）**：
   - `removeVisibleProp`：清理字段后立即调用 `syncClassmates(scene.root, node)`，彻底删除所有同选择器元素上的对应属性；
   - `addVisibleProp`：添加属性列表后同步联动同类伙伴；
   - `updateStyle` 与 `updateStyleTransient`：当属性传入 `undefined` 时彻底从 `style` 对象中 `delete`，避免残留空键；
   - `syncClassmates` 升级：将 `style`、`visibleProps`、`pseudoStyles` 完整全量深拷贝给所有同类名、同关系选择器元素，保证同类元素 100% 结构一致；
   - 伪类样式（`:hover/:active` 等）也接入 `updatePseudoStyle` 和 `removePseudoStyle` 专用 store 方法，删除或修改伪类属性时同样自动全量同步。

### 自测
- `tsc --noEmit` ✓；`electron-vite build` ✓（css 123.95kB / js 691.35kB）。
- 客户端实时重启验证：对带同名类（如多个 `.card`）的任意一个元素点击「×」删除属性，所有同类元素的该属性均同步移除，不会产生任何类名/ID 冲突与黄色警告！
